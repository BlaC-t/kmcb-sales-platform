# 测试与验收策略

## 1. 测试金字塔

- Domain unit：状态机、规则、单位、评分、图校验、设备数量/能力。
- Property-based：单位换算、图遍历、数量与范围不变量。
- Repository integration：与 121 同版本的真实 MySQL + migration + 外键/CHECK/generated-column 唯一约束。
- API contract：OpenAPI schema、权限、幂等、并发冲突。
- Worker integration：Outbox、重试、幂等、失败恢复。
- UI component：需求表单、节点/边、差异、状态提示。
- E2E：BMS 认证→平台建项→企业展示→客户问诊→推荐→销售设备选择→初步文件权限审核→现场交付→工程修改→审核→发布。
- Security：授权、上传、Electron IPC、依赖和密钥。

## 2. 金标准案例

上线前由工艺团队提供 10–20 个覆盖首批范围的案例，每个包含：

- 经确认输入与来源；
- 可接受工艺模块集合（允许多个正确答案）；
- 明确不允许的工艺/设备；
- 设备类型/型号可接受范围；
- 关键工程规则；
- 预期警告、缺失信息和人工设计条件；
- 工艺负责人签字/确认状态。

不要把某一历史设计当成唯一真值；使用允许集合、红线和工程师评分。

## 3. 关键验收场景

### A. 正常闭环

销售通过 BMS 认证后在 Sales Platform 新建项目，完成企业展示和客户问诊，系统生成至少两个候选；每个适用工艺段显示多个设备选项；销售冻结初步文件，指定权限审核人批准后现场交付；工程师替换设备并填写原因；工程审核批准；发布包包含正确流程说明、分段设备、版本和差异。

### A2. 客户演示模式

客户模式只能访问已发布且标记 customer-safe 的公司、乌兹别克斯坦子公司、生产能力、产品功能和授权案例；无法通过 URL、缓存或开发者工具获得内部评分、规则原文和其他客户数据。

### A2.1 内容维护与多语言发布

内容编辑者不改代码即可修改标题、正文、图片和排序；同一页面结构可分别维护 `zh-CN`、`en`、`ru`、`uk`。源字段变化只将相关译文标记为 `STALE`。缺关键翻译、alt text、媒体 variant、客户安全确认或有效权利时发布被阻止。成功发布后 Web/Electron 在 ETag 变化时取得同一 release；下载中断/checksum 错误继续使用上一完整版本。历史会谈仍能还原当时页面、locale 和媒体 checksum。

### A3. 多设备选择与打印

同一工艺段至少可比较两个适用型号。销售调整型号或运行/备用数量后重新校核；冻结 handout 后再次修改会生成新销售修订/新 handout，旧 PDF/DOCX 内容、审核决定和 checksum 不变。

### A3.1 初步文件权限审核

无 `customer.handout.review` 权限的销售不能批准或交付；有权限但不是固定团队负责人职级的指定人员可以审核。默认生成者不能自审。批准后若 manifest、locale、PDF/DOCX 或免责声明变化，旧批准失效且必须生成新 handout。工艺工程师不参与该现场审核，文件仍显示未经工艺审核。

### A4. 工程交接

工程师接收时能查看客户原始问答、标准化需求、算法候选、销售选择前后差异、全部备选设备、客户偏好、警告和客户已经带走的 handout 编号。

### B. 道路限重

候选设备运输重量超过桥梁限重时被排除或强制分体方案，不能用高相似度覆盖。

### C. 缺关键试验数据

系统返回需人工确认/试验，不伪造回收率或正式流程。

### D. 闭路循环

磨矿—分级返砂可保存、遍历和报告；未标记异常环被阻止。

### E. 数据版本变化

设备 V4 发布后，旧推荐仍引用 V3；系统标记可能受影响并可重跑，旧报告不变化。

### F. 并发编辑

两名工程师编辑同一修订，旧 rowVersion 保存被拒绝并给出可合并差异。

### G. 重复发布

网络重试/双击只生成一个 release number 和一个正式 manifest。

### H. 权限隔离

销售不能查看无权限项目；工程师不能批准自己的提交；服务账号不能人工批准；没有 `sales_platform.data_maintain` 的用户不能进入数据更新中心或提出数据变更。

### I. BMS 认证与平台建项

未通过 BMS 认证无法打开受保护功能；token 过期、退出和权限变更按契约生效。创建 Project 不需要外部销售/CRM/报价项目 ID，且 BMS 不保存 Sales Platform 业务 Project。

### I2. BMS 管理控制面

BMS 菜单、按钮、BFF 和 Sales Platform 服务端对同一最终权限映射得出一致结果。菜单只出现一个“审核与发布”，权限页命名为“权限”，不出现“发布中心”“审核待办”“权限与集成”或“审计与运行”。内容/翻译/设备/案例/规则/handout/发布页面只显示授权范围；默认列表不平铺敏感字段，结构化详情可追溯版本/来源/影响，原始视图需要额外权限。BMS 数据库不存在平台项目、推荐或目录数据副本；发布命令只通过 Sales Platform API。Sales Platform 不可用、缓存过期或权限被撤销时，批准和发布均被阻止。

每个新增页面（含表格/列表页）均可在 BMS 菜单管理中找到对应“页面”记录，按钮有对应“权限”子项。登录后路由来自 `/permission/getUserPromissions`；禁用/撤销菜单记录后页面随权限结果消失。检查 `src/store/modules/routes.ts`、`src/router/index.ts` 和 legacy `inject*` 不得出现 Sales Platform 新业务路由，页面中的 `hasPermission(...)` 与最终 `functionCode` 完全一致。

### J. 多语言与时区

同一 handout 可分别生成 `zh-CN`、`en`、`ru`、`uk` 版本；俄语和乌克兰语内容不可混用。客户关键翻译缺失时阻止交付。API/数据库 UTC 时间相同，上海、塔什干、基辅等 IANA 时区的 UI 与 PDF/DOCX 显示符合当地偏移和夏令时规则。

### K. Phase 1 LLM 实验

每次 LLM 调用可追溯 purpose、model、prompt/template、输入 checksum、输出、token/成本和人工处理结果。幻觉、错误翻译或敏感数据策略命中时能拒绝/阻止；任何 LLM 输出不能直接进入 PUBLISHED 工程事实。

### L. 非标准产品 Excel 导入

用 `圆振动筛产品参数表-260626.xlsx`、`洗矿机产品在销售版本明细表(2026.04洗矿机更新).xlsx` 和 `直线筛产品在销售版本明细表-2026.4.20.xlsx` 作为首批金标准。必须识别 4 个 Sheet 和 9 个 logical regions，不能把直线筛工作簿中的分级机当成直线筛。验证重复表头、区域中途换字段、合并空白继承、同型号多图号、空型号图号变体、范围符号、功率阵列、双重量语义、空价格以及 Excel 日期序号异常。

导入结果必须显示 NEW_MODEL、NEW_VARIANT、UPDATE、FORMAT_ONLY、NO_CHANGE、CONFLICT 和 INCOMPLETE；每个字段可回到 Sheet/单元格。文件中缺席不能自动下架；无审核不能写 published 设备数据；重复上传/发布保持幂等。

## 4. 推荐引擎验收门槛

- 金标准中硬约束违规为 0。
- 每个保留/排除候选都有机器可读 reason code 和用户说明。
- 结果可用相同快照/依赖重现。
- 未覆盖场景安全回退，而不是空白或强行推荐。
- 工艺负责人确认首批白名单内的 Top-K 可用性门槛。

具体 Top-K 指标和阈值需用真实案例基线后确定，不在无数据时虚构百分比。

## 5. 数据验收

- DDL 从空库执行成功并可重复在迁移框架中验证。
- 外键、唯一、check、发布版本约束生效。
- 原始值/单位与标准化值/单位可追溯。
- AI 提取不能直接出现在 published 查询。
- 附件 checksum、权限和来源位置可回查。
- 会谈固定内容/问卷版本，历史回答和客户打印件不会被后续内容更新改变。
- 初步文件审核记录与 manifest/file checksum 一致，无法批准内容漂移版本。

## 6. Electron 验收

- `nodeIntegration=false`、context isolation/sandbox 生效。
- Renderer 无法直接访问 Node/fs/process 敏感能力。
- IPC 参数和 sender 校验测试。
- CSP、导航、新窗口和外部链接策略测试。
- 断网/重连不重复提交；草稿恢复可解释。
- Windows 与 macOS 在同一版本完成 BMS 登录、会谈、PDF/DOCX 预览/保存/打印和自动更新验收。
- 两个平台无需更新安装包即可取得新 ContentRelease；断网时只显示最后一次校验通过的已发布内容，不显示草稿或半下载页面。

## 7. 报告验收

- 报告与 `release_manifest` 内容一致。
- 页眉/页脚含项目、发布号、版本、状态、当地生成时间、IANA 时区与 UTC 偏移。
- 每个工艺段都有目的、输入/输出、设备与数量。
- 风险、假设、缺失信息和适用边界不可被隐藏。
- 被替代/撤回版本下载时有明显水印。
- PDF 与 DOCX 从同一 manifest 生成；关键字段、语言、设备数量和 checksum 对应关系一致。

## 8. 证据边界

代码测试通过不等于真实 BMS 身份集成、Windows/macOS 安装包、生产数据库执行、LLM 数据出域批准或最终报告已交付。验收报告必须分别陈述：代码/自动测试、浏览器/Electron 可见行为、各操作系统安装包、迁移执行、集成环境、生产发布和对外发送状态。
