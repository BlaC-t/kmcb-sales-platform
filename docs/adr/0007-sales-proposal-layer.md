# ADR-0007：在算法候选与工程方案之间增加销售方案层

- Status: Proposed
- Date: 2026-08-27

## Context

真实销售流程不是“算法推荐后立即交给工程师”。销售会在客户面前比较每个工艺段的多个设备型号，调整型号与数量，打印流程图和设备清单给客户，然后把这次会谈与选择结果交给工艺流程工程师。

如果直接修改算法候选，会失去推荐复现能力；如果直接修改工程修订，会把未经工程确认的现场选择混入工程生命周期；如果只把变化保存为自由文本，工程师无法可靠复现客户看到的版本。

## Decision

新增独立 `SalesProposal` / `SalesProposalRevision` 聚合：

- 算法候选不可变，包含每段多个设备选项。
- 销售选择候选后创建销售修订，可切换设备和调整数量，但不能修改工艺拓扑。
- 销售修订持续执行能力、运输、电力等校核；超出推荐清单必须记录理由并标记工程确认。
- 客户初步打印件从冻结销售修订生成不可变 manifest，并带明确免责声明；只有持有 `customer.handout.review` 的指定人员审核通过后才可交付。
- 提交工程后冻结销售修订，由它创建 `SolutionRevision 1` 和工程交接记录。

## Consequences

增加了表、状态与页面数量，但能够分别追溯算法推荐、销售现场选择、客户带走版本和工程最终结论。销售现场灵活性不再以污染算法或工程记录为代价。

## Rejected Alternatives

- 直接编辑算法候选：破坏可复现性。
- 直接创建工程修订供销售编辑：权限与状态语义错误。
- 只把销售变更写备注：无法结构化校核、比较或重放打印件。
