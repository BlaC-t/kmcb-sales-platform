# 前台企业展示与二级页面规划

## Status

Draft — 初版信息架构规划。用于确认页面层级、讲解方式与后台维护边界；后续再补充逐页内容脚本、视觉设计、数据字段、权限矩阵和验收细则。

## Summary

Sales Platform 前台采用“沉浸式开屏 + 五大板块 + 沉浸式闭幕”的整体结构。五大板块允许拆分二级页面，以改善销售讲解节奏、自由跳转和内容维护；但完整页面树不直接等同于标准讲解路线。

建议首版建立 **16 个固定二级页面/任务步骤**，并复用 **设备详情、案例详情 2 个动态模板**。后台不为每个二级页面建立独立管理菜单，而是在统一“内容与媒体”工作台中通过页面树管理。

## Context and Scope

本规划覆盖销售人员面向客户使用的企业展示部分：

- 沉浸式开屏与讲解导航；
- 企业综合实力；
- CIBA 数字智控中心；
- 产品与服务；
- 全球案例；
- 选厂工艺模拟器；
- 沉浸式闭幕；
- 上述页面在后台的统一维护方式。

本规划延续现有系统边界：Sales Platform 是独立业务系统，使用 BMS 身份与权限能力；BMS 内的管理控制面只作为内部维护入口，不复制 Sales Platform 领域数据。

## Goals

1. 让每个二级页面回答一个清晰的客户问题，避免单页内容过长。
2. 同时支持标准讲解、自由讲解和临时深挖。
3. 允许内容按页面独立维护、预览、审核和发布。
4. 保持产品、案例、工艺和媒体数据统一复用，不因前台拆页产生重复数据。
5. 控制导航深度，避免前台和后台同时演变成复杂树形系统。
6. 为后续多语言、地区范围、离线发布和版本追溯保留结构基础。

## Non-Goals

当前版本暂不确定：

- 每页最终文案、销售话术和旁白；
- 每页视觉布局、动效、三维镜头和素材清单；
- 实时看板的具体指标、刷新频率和数据接口；
- 设备选型、工艺匹配和数量计算规则；
- 精确 URL、组件名、数据库表和 API；
- 每个角色的最终 BMS `functionCode`；
- 标准讲解路线的最终时长和地区版本。

以上内容在页面结构确认后分阶段补充。

## Constraints

- 前台导航最多采用“一级板块 → 二级主题页 → 动态详情”三层结构。
- 不建立固定第四级导航；设备型号、案例和工艺节点由模板及领域数据动态生成。
- 标准讲解不自动遍历所有二级页面，而是引用重点页面形成讲解路线。
- 产品、案例和工艺数据只能来自统一领域数据源，不能在 CMS 页面中复制一份。
- 客户模式不得显示内部评分、成本、规则原文、未发布结论或其他客户资料。
- 页面、翻译、媒体和讲解路线均需经过版本化审核与发布后才能对客户显示。
- Web/Electron 应记录当前会话使用的内容发布版本和讲解位置。

## Proposed Design

### 1. 总体结构

```text
前台销售展示系统
  沉浸式开屏
  五大板块
    企业综合实力
    CIBA 数字智控中心
    产品与服务
    全球案例
    选厂工艺模拟器
  沉浸式闭幕
```

开屏负责建立品牌氛围、选择语言并进入讲解；闭幕负责总结企业、数字化、产品、工艺、案例和海外服务价值。开屏和闭幕按“场景”管理，不继续拆分二级页面。

### 2. 企业综合实力

板块首页先形成“为什么客户可以信任 CIBA”的整体判断，再按客户关注点进入以下二级页面：

| 二级页面 | 主要内容 | 首版处理方式 |
|---|---|---|
| 企业画像 | 企业介绍、总部与产业园、发展历程、荣誉资质、全球业务布局 | 历程、荣誉和全球布局作为同页区块，不继续拆页 |
| 智能制造 | 工厂规模、生产线、数控加工、机械臂、质检与生产数据管理 | 以制造过程和可验证能力为主线 |
| 研发与工程 | 设备研发、工艺设计、技术成果、数字研发团队、自研软件和工程计算 | 技术型客户可从自由讲解直接进入 |
| 全球本地服务 | 海外分公司/4S 店、本地团队、售后支持、备件、实验室和海外仓规划 | 区分已经具备的能力与未来规划 |

标准讲解默认进入“板块首页 → 智能制造 → 全球本地服务”；研发与工程作为可选技术分支。

### 3. CIBA 数字智控中心

该板块回答“CIBA 如何实时看见、理解和管理生产现场”。建议拆分：

| 二级页面 | 主要内容 | 关键边界 |
|---|---|---|
| 实时工厂 | 车间、加工/焊接、质检/调试多视角实时画面 | 必须显示画面时间、在线/离线状态和替代内容 |
| 生产运营 | 环境指标、设备开机率、工位运转率、在产设备和趋势摘要 | 首版指标后续由数据负责人确认 |
| 物流与周转 | 行车、大型部件流转、仓储和关键周转节点 | 不在本页重做仓储或生产管理系统 |

该板块只展示 CIBA 自身工厂的实时数字化能力。面向客户销售的数字系统继续归属“产品与服务”，避免两处内容重复。

### 4. 产品与服务

板块首页先讲清“矿机设备 + CIBA 数字系统 + EPC 服务”的完整价值组合，再进入三个二级入口：

| 二级入口 | 主要内容 | 深层页面处理 |
|---|---|---|
| 矿机设备 | 分类、搜索、筛选、精选设备和推荐设备 | 点击设备后进入统一动态设备详情模板 |
| CIBA 数字系统 | 感知层、保障层、决策层，以及设备生产、服务和运营管理能力 | 三层能力首版保留在一条叙事页内 |
| EPC 服务 | EPC 价值、全流程里程碑、业务范围、团队和资质 | 以里程碑区块组织，不为每个阶段拆页 |

动态设备详情模板建议包含：

1. 总览与应用场景；
2. 360°查看和设备实拍；
3. 工作原理与企业优势；
4. 数字化亮点与管理收益；
5. 型号与技术参数；
6. 关联工艺与案例。

设备型号不建立固定导航页，由设备详情模板按已发布产品数据动态加载。

### 5. 全球案例

建议采用“建立全球覆盖感 → 搜索证据 → 查看项目详情”的结构：

| 页面 | 主要内容 | 首版行为 |
|---|---|---|
| 全球项目总览 | 世界地图、国家/地区覆盖、项目统计、精选案例 | 标准讲解从这里进入最相关的精选案例 |
| 案例探索器 | 国家、矿种、工艺、处理量、设备和关键词筛选 | 地图与列表作为同一页面的两种视图 |
| 动态案例详情模板 | 项目信息、客户需求、原矿、实际工艺、设备、问题解决、结果、媒体和团队故事 | 只显示已授权、已脱敏、已发布内容 |

标准讲解不进入完整筛选流程，默认选择与当前客户地区、矿种或工艺最相关的一个案例。

### 6. 选厂工艺模拟器

模拟器不是普通内容层级，而是一条有状态的任务流。建议拆为四个步骤：

| 步骤 | 页面目标 | 首版内容 |
|---|---|---|
| 01 矿况输入 | 收集形成初步匹配所需的最小条件 | 矿种、粒度、泥度/洗矿、处理量；支持未知和待确认 |
| 02 匹配结果 | 展示标准和相似工艺候选 | 适用条件、不适用条件、推荐说明和待确认项 |
| 03 工艺与设备 | 展示流程及每个节点的设备选择 | 简易流程图、3D/视频入口、节点、型号、单台/并联数量 |
| 04 案例与总结 | 用相似案例解释结果并形成沟通总结 | 关联案例、假设、风险、缺失资料和后续工程交接 |

步骤 3、4 不复制产品库或案例库。设备和案例通过详情侧栏或独立详情路由打开；关闭后返回原步骤并保留当前输入、匹配结果和讲解位置。

### 7. 标准讲解与自由讲解

完整页面树与标准讲解路线必须分开管理：

| 模式 | 使用范围 | 交互方式 | 建议规模 |
|---|---|---|---|
| 标准讲解 | 从完整树中选择重点页面、章节或动态详情 | 下一页/上一页、预计时长、可选分支 | 7–10 个主要节点 |
| 自由讲解 | 当前账号和地区获授权的全部页面 | 板块导航、全局设备/案例搜索、最近访问、返回主线 | 不限制固定路线 |
| 临时深挖 | 单个设备、案例或工艺节点 | 侧栏或详情路由，关闭后恢复原位置 | 按客户问题临时进入 |

标准讲解路线应被建模为可配置播放清单，而不是复制页面内容。路线只保存页面/章节引用、顺序、预计时长和可选分支。

### 8. 后台管理方式

所有固定页面统一在“内容与媒体”工作台的页面树中管理，不为每个页面建立独立 BMS 一级菜单。

后台按页面类型提供不同编辑器：

| 页面类型 | 适用范围 | 管理内容 | 权威数据来源 |
|---|---|---|---|
| 叙事页 | 企业画像、制造、研发、本地服务、EPC | 区块、多语言、媒体、排序、地区范围 | CMS 页面/修订 |
| 实时展示页 | 实时工厂、生产运营、物流周转 | 说明、布局、卡片配置、离线替代内容 | CMS 配置 + 授权实时数据 |
| 集合页 | 设备目录、全球总览、案例探索器 | 引导文案、精选项、默认筛选、可见字段 | CMS 配置 + 产品/案例数据 |
| 动态详情 | 设备详情、案例详情 | 模板、字段分组、媒体位置和客户安全投影 | 统一产品/案例数据库 |
| 任务步骤 | 模拟器四步 | 说明、帮助、默认值和结果解释 | 流程代码 + 工艺规则 + CMS 文案 |
| 场景 | 开屏、闭幕 | 镜头顺序、媒体、旁白和跳过行为 | CMS 场景配置 |

每个页面统一提供以下管理页签：

1. 内容区块；
2. 多语言；
3. 媒体；
4. 导航与讲解编排；
5. 地区与内容权限；
6. 客户模式预览；
7. 版本、审核与发布。

### 9. 二级页面拆分规则

一个主题满足以下至少两项时，建议拆成独立二级页面：

- 销售会从自由讲解直接跳入；
- 能独立回答一个客户问题；
- 内容负责人或更新频率明显不同；
- 需要独立地区范围、权限或发布节奏；
- 内容超过一次自然讲解的单屏或单主题容量。

以下情况不拆页，改用区块、页签、筛选器或动态模板：

- 只是同一资源的字段或媒体类型；
- 离开父页面后没有独立语义；
- 只有一张图、一段视频或少量参数；
- 来自同一个设备/案例详情模板；
- 拆开后会造成标准讲解频繁跳转。

## Architecture Views

### 页面与数据关系

```text
CMS 页面树
  ├─ 叙事内容、翻译、媒体位置、导航和地区范围
  ├─ 引用产品目录 ──> 动态设备详情
  ├─ 引用案例库 ────> 动态案例详情
  ├─ 引用工艺与规则 ─> 模拟器步骤和结果
  └─ 生成 ContentRelease ─> Web / Electron 客户展示

讲解路线
  └─ 引用已发布页面/章节/动态详情，不复制内容
```

## Alternatives Considered

### 所有内容放在五个长页面中

页面数量少，但单页过长、自由跳转困难、内容负责人难以独立维护，也不利于按地区和语言发布，因此不采用。

### 为每一项内容建立独立页面

维护粒度看似精确，但会产生过深导航、重复页面、频繁跳转和大量后台菜单，因此不采用。

### 标准讲解自动遍历完整页面树

实现简单，但会让讲解时长失控，并迫使销售跳过大量无关内容。采用可配置讲解路线，允许不同地区、客户类型和预计时长选择不同节点。

## Tradeoffs

- 二级页面增加页面与版本数量，但换来清晰讲解、直接跳转、独立发布和更好的内容责任边界。
- 动态详情模板减少重复维护，但要求产品和案例数据质量足够稳定。
- 可配置讲解路线增加后台编排能力，但避免为了不同客户复制整套页面。
- 三层深度限制降低自由度，但能保护销售现场的导航效率。

## Cross-Cutting Concerns

- **多语言**：首期继续支持 `zh-CN`、`en`、`ru`、`uk`；源语言变化只标记相关译文为过期。
- **地区与客户安全**：案例、联系方式、媒体和未来规划按地区及内容权限过滤。
- **实时数据可靠性**：实时页必须显示数据时间、连接状态和不可用时的安全替代内容。
- **离线使用**：Electron 只切换到完整校验通过的 ContentRelease；失败时保留上一完整版本。
- **可追溯性**：会话保存内容版本、语言、讲解路线、自由跳转和模拟器输入快照。
- **性能**：3D、360°、实时流和视频按需加载；标准讲解首屏优先预取下一节点。
- **可访问性**：键盘导航、字幕/文字替代、减少动态效果模式、对比度和长语言布局需后续验证。

## Rollout and Migration

### Phase 0：确认结构

- 确认本文件中的板块、二级页和动态模板边界；
- 确认标准讲解只引用重点节点；
- 为每个二级页面指定业务内容负责人。

### Phase 1：建立页面骨架

- 建立开屏、五大板块首页、二级页面和闭幕的空页面树；
- 建立页面类型、统一管理页签和预览能力；
- 选择一个板块跑通中文草稿、审核、发布和回滚。

### Phase 2：接入统一数据

- 接入设备集合及动态设备详情；
- 接入案例探索器及动态案例详情；
- 接入模拟器步骤与工艺/匹配数据；
- 验证详情跳转后会话状态能够恢复。

### Phase 3：讲解编排与多语言

- 建立标准讲解路线编辑；
- 配置首条 7–10 节点标准路线；
- 完成四语言、地区范围、离线缓存和会话版本记录。

### Phase 4：逐页细化

- 补充每页内容目标、讲解话术、素材和数据字段；
- 明确实时指标、三维/视频脚本和动效；
- 增加逐页交互、异常、性能和可访问性验收标准。

## Open Questions

以下问题不阻塞初版页面结构，但应在详细设计阶段逐项确认：

1. 标准讲解需要按地区、客户类型还是预计时长维护多套路线？
2. 企业画像中的全球业务布局是否需要独立地图页，还是保留为区块？
3. 数字智控中心首期可稳定提供哪些实时数据和视频流？
4. CIBA 数字系统是否需要按感知层、保障层、决策层进一步拆页？
5. 设备详情的 360°、真人比例和原理动画哪些设备首期具备素材？
6. 全球案例可以对外展示的国家、客户名称、评价和媒体范围是什么？
7. 模拟器首期是演示型匹配还是可以生成客户初步文件的正式流程？
8. 开屏和闭幕是否需要按地区或客户类型配置不同版本？

## Decision

建议以本文件作为初版基线：

- 保留五大一级板块；
- 建立 16 个固定二级页面/任务步骤；
- 使用设备详情和案例详情两个动态模板；
- 开屏和闭幕保持为单一场景；
- 标准讲解采用 7–10 节点的可配置路线；
- 自由讲解开放全部已授权页面；
- 所有固定页面在统一后台页面树中管理，不新增对应的一级后台菜单。

本决策处于 Draft 状态。下一轮评审应先确认页面边界和讲解路线原则，再进入逐页详细设计。
