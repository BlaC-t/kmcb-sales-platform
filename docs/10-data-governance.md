# 数据治理与持续更新

## 1. 原则

自动化负责提取、映射、校验和提出变更；人对工程事实的发布负责。任何 OCR/LLM/Excel 导入都不能直接更新已发布设备、案例或规则。

只有从 BMS 权限映射获得 `sales_platform.data_maintain` 的主体可以进入数据更新中心、导入资料或提出正式数据变更。该入口权限不等于高风险发布权限；设备能力、规则和案例仍执行提出/审核/发布分离。

BMS 内的 Sales Platform 管理中心是首选内部入口，但不是数据宿主。页面使用“摘要列表 → 结构化详情 → 受限原始/证据”的三层展示：有权人员可追溯全部业务事实、版本和来源，不把 83 张表或全部列平铺在一个页面，也不展示密钥、凭据和未授权客户资料。所有变更通过 Sales Platform API 进入下述流水线。

## 2. 数据流水线

```text
上传/同步
  → 文件校验与去重
  → OCR/表格/文本提取
  → 同义词映射和单位归一化
  → extracted_fact 暂存
  → 规则/范围/冲突校验
  → data_change_request
  → 工程/数据审核
  → 新实体版本发布
  → 特征快照重建
  → 影响范围分析
```

产品 XLSX 在“上传/同步”和 `extracted_fact` 之间增加工作簿结构层：Workbook → Sheet → logical region → mapping profile → candidate record。一个文件可以产生多个产品类型和多个变更申请；陌生格式必须先确认 header、区域、字段和单位。详细设计见 `docs/product-import/design.md`。

## 3. 来源与证据

每条高价值事实至少关联：

- 来源文档/系统和 checksum
- 页码、表格、单元格或 bounding box
- 原始文字/值/单位
- 标准化值/单位
- 提取方式与模型/解析器版本
- 置信度（仅表示提取确定性，不代表工程真实性）
- 审核人和发布日期

Excel 来源还必须保存 Sheet 名、单元格/合并范围、raw value、formatted text、number format、mapping profile/parser 版本。仅保存底层数值会把 `6/8` 一类工程区间误读为 Excel 日期序号。

## 4. 质量维度

- Completeness：关键字段覆盖率
- Validity：类型、单位、范围和字典合法
- Consistency：跨来源/跨字段是否冲突
- Uniqueness：型号、案例、文档是否重复
- Timeliness：是否到复核期
- Traceability：能否回到来源位置
- Engineering reliability：厂家、试验、设计、运行实测等来源等级

质量问题级别：`BLOCKER`、`MAJOR`、`MINOR`、`INFO`。

## 5. 复核策略

不同数据类型有不同 `freshness_policy`：

| 数据 | 示例策略 |
|---|---|
| 设备几何/重量 | 规格版本变化或年度复核 |
| 能力包络 | 新试验/运行数据到达或定期复核 |
| 价格/交期 | 高频复核；不进入纯技术推荐时可分离 |
| 工程规则 | 标准/经验变化或年度评审 |
| 历史案例 | 设计、投产、稳定运行三个阶段补充 |

周期必须配置，不硬编码。超过复核期不一定立即失效，但会降低证据等级或阻止高风险推荐。

## 6. 影响分析

发布以下数据后产生事件：设备规格、规则集、历史案例、实际表现。Worker 根据 `recommendation_dependency` 查询受影响 Run/Release：

- 只标记 `POTENTIALLY_IMPACTED`；
- 不覆盖历史推荐或报告；
- 展示变化字段、旧/新值和受影响原因；
- 允许项目负责人使用最新快照重跑；
- 正式已发布方案是否需要复审由风险规则决定。

## 7. 数据责任

| 数据 | 提出 | 审核 | 发布 |
|---|---|---|---|
| 矿石/案例事实 | 数据管理员/工程师 | 工艺工程师 | 数据发布人 |
| 设备规格 | 产品/数据管理员 | 设备专家 | 数据发布人 |
| 工程规则 | Rule Owner | 工艺审核人 | Rule Publisher |
| 实际运行表现 | 项目/售后 | 工艺/数据负责人 | 数据发布人 |
| 同义词/字典 | 数据管理员 | 领域负责人 | 数据发布人 |
| 企业/海外子公司/生产与产品展示 | 市场/销售/海外团队 | 内容负责人/合规 | Content Publisher |
| 客户问卷模板与字段映射 | 产品/销售/工艺 | 工艺与数据负责人 | Questionnaire Publisher |
| 中文/英语/俄语/乌克兰语术语与模板 | 内容/数据维护人或 LLM 草稿 | 对应语言审核人 + 领域负责人 | Content/Translation Publisher |

企业展示内容和问卷虽然不是设备工程事实，也必须版本化。会谈需要固定当时使用的内容/问卷版本；删除或修改当前内容不能改变历史客户会谈记录。

企业展示内容使用专用 CMS 工作流，不与工程主数据变更混在一个总权限中。页面结构、源语言、各 locale 翻译和媒体分别记录 checksum。源语言变化只把受影响译文标记为 `STALE`；媒体权利到期或客户授权撤回会阻止进入新 release，并触发已发布内容影响告警。发布形成不可变 ContentRelease；回滚保留原因、操作者、UTC 时间和被恢复 manifest。

## 8. AI 使用边界

Phase 1 即允许开展受控 LLM 实验：文档分类、OCR 后结构建议、同义词候选、字段映射、中文/英语/俄语/乌克兰语翻译草稿、说明草稿、证据定位和候选流程/设备建议。

禁止自动正式化：设备极限能力、工艺适用条件、回收率、数量、强制规则、正式流程和审核决定。

模型输出必须保存 purpose、provider/model、prompt/template 版本、UTC 时间、输入文档 checksum、项目/用户时区、token/成本、延迟、输出引用和人工接受/拒绝/修改结果，便于评估误差。未经数据出域批准，敏感客户资料不得发送到外部模型。

LLM 翻译只能生成 `DRAFT`。客户关键术语、免责声明和 PDF/DOCX 内容在目标 locale 发布或交付前必须由对应语言审核人确认；不得把俄语和乌克兰语当成同一语言版本。

## 9. 质量看板

- 待审核变更数量和等待时间
- BLOCKER/MAJOR 未关闭数量
- 过期设备/规则/案例
- 无来源关键字段
- 冲突事实和重复型号
- 每类导入的接受/拒绝率
- AI 提取字段级准确率
- 发布后被回滚/修正的变更

质量看板可以作为 BMS 管理总览的投影，但点击后必须回到具体质量问题、来源和变更申请；总览不提供直接批准/发布捷径。
