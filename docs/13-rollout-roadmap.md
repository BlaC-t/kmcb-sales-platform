# 实施路线图

## Phase 0：发现与金标准（2–4 周）

交付：术语表、首批范围、角色/审批、BMS 认证/权限/BFF/菜单契约、平台后端部署决定、金标准案例计划、数据清单和设计批准。可用源文件由用户后续提供，在此之前不虚构案例内容。

退出条件：工艺负责人确认允许/禁止边界；BMS 身份/权限有书面契约；Sales Platform 内建项目模型和 MVP 验收案例可执行。

## Phase 1：数据底座与人工工程工作台（6–10 周）

交付：结构化企业展示 CMS、媒体库、四语言矩阵、ContentRelease/离线缓存、BMS 管理中心只读总览与内容/handout 审核、产品 Excel 只读导入预览与字段 diff、客户演示模式、平台建项、引导问卷、销售方案、初步文件权限审核、PDF/DOCX、项目/用户时区、主数据、设备/案例版本、流程图编辑、数据治理、审核发布和基础报告。Phase 1 同时加入受控 LLM 实验，用于提取、映射、翻译/说明草稿和候选建议；推荐仍可由工程师模板与确定性校核兜底。

退出条件：内容人员无需改代码即可完成改字/换图→四语言审核→发布/回滚，Windows/macOS 无需更新安装包即可原子取得新 release；同时无需 LLM 也能完成 BMS 登录→平台建项→客户问诊→销售初步方案→权限审核→现场交付→工程→正式发布；四语言/PDF-DOCX、版本/审计/权限可靠；LLM 有可量化接受/拒绝基线。

## Phase 2：推荐 MVP（6–10 周）

交付：硬约束、相似案例、流程模板组合、设备初选、分项评分、解释和安全回退。

退出条件：金标准硬约束违规 0；工艺团队确认 Top-K 候选对首批白名单有用。

## Phase 3：客户端与试点（4–8 周）

交付：前端独立仓库、Windows/macOS Electron 签名包、自动更新、监控、Runbook、试点培训；BMS 认证契约在 Phase 1 前已经打通，不再等待外部销售项目引用。

退出条件：真实试点项目闭环；销售只拿到已发布版本；工程师改动和回退原因可度量。

## Phase 4：优化与反馈闭环

交付：精细物料/水量平衡、实际运行反馈、影响分析、更多矿种/工艺、价格/交期可选模块、多目标优化。

## 工作流分轨

| 轨道 | 主要工作 |
|---|---|
| Product/Process | 企业展示、客户会谈、问卷、规则、金标准、打印/报告模板、审核门槛 |
| Data | 词典、设备/案例导入、来源、质量、复核 |
| Backend | 领域、数据库、API、Worker、Outbox、推荐 |
| Frontend | 独立仓库；销售看板/演示模式、Web/Electron、设备比较、流程画布、初步文件审核、差异、数据中心 |
| Integration | BMS 认证/权限交换、管理中心 BFF/菜单/专用权限码、Windows/macOS 签名更新 |
| QA/Ops | 自动化、金标准回归、安全、部署、监控、Runbook |

8. Coverage Expansion

## 风险缓释

- 数据少：先规则/案例/模板，不承诺 ML。
- 规则争议：规则 owner、测试、版本和双人发布。
- 范围膨胀：按矿种/工艺/设备白名单。
- BMS token 契约不清：Identity Adapter 隔离，先 mock contract；不把平台建项依赖 BMS 项目。
- LLM 价值/风险不清：Phase 1 小范围、可关闭、全记录，确定性流程始终可用。
- 多语言不足：关键术语/免责声明缺翻译时阻止交付，不静默回退。
- 工程师不采用：Phase 1 先把人工工作台做有用，再叠加算法。
- 解释不足：理由/排除/证据从数据模型层强制，不靠报告后补。

## 团队建议

MVP 最小跨职能：产品/业务 1、工艺负责人 1、工艺工程师 1–2、后端 2、前端/Electron 1–2、数据/算法 1–2、QA 1、运维/安全兼职。实际排期需按现有团队和资料质量调整。
