# React + Electron 前端设计

## 1. 信息架构

以下信息架构属于独立 React/Electron/Web Sales Platform。BMS 另设 `Sales Platform 管理中心`，首期承载内容、翻译、数据治理、审核与发布、项目/工程记录和权限投影；不在 BMS 重做客户演示、销售设备比较和工程流程图画布，也不设置独立“审计与运行”菜单。

BMS 管理端的所有新增页面（包括表格/列表页）必须在 BMS 菜单管理配置，由 `/permission/getUserPromissions` 动态生成菜单和路由。Vue 页面放在 `src/views/...`；禁止把业务页面写入 `src/store/modules/routes.ts`、`src/router/index.ts` 或新增 legacy `inject*`。按钮能力作为菜单下的“权限”子项，精确匹配最终 `functionCode`。

## 2. 关键页面

### 销售看板首页与演示模式

- 打开 Web/Electron 后先通过 BMS 认证；前端不保存 BMS 口令，也不自行决定权限。
- “开始客户会谈”作为主入口，最近会谈/待补充/待工程接收作为辅助入口。
- 开始会谈时在 Sales Platform 创建 Project，不要求选择已有 BMS/CRM/销售项目。
- 企业展示包含公司、乌兹别克斯坦子公司、生产能力、产品功能和授权案例。
- 演示模式使用大字号、全屏导航和客户安全投影；隐藏内部菜单、评分权重、规则原文、其他客户、内部价格和数据治理入口。
- 展示内容来自已发布内容版本，可按语言和地区切换。
- 第一部分像公司网站一样由结构化 CMS 驱动：页面树 + 固定区块模板 + 媒体库，不把公司文案和图片写死在 React/Electron 包里。

### 引导式客户问诊

- 使用分步会谈导航而不是一次展示全部数据库字段。
- 每一步同时显示“为什么要问”“客户不知道怎么办”和单位示例。
- 支持销售代录客户原话、未知、估计值、附件和后续补充标记。
- 右侧只显示会谈进度、阻断项和待补充信息；工程内部规则细节不向客户展开。

### 销售方案与设备比较

- 中央显示客户可读流程图；选择工艺段后，右侧显示 1–N 个设备卡片。
- 设备卡片使用统一比较字段：型号、能力、数量、功率、运输重量、适用条件、推荐理由和工程确认状态。
- 销售可切换设备、修改运行/备用数量、记录客户偏好；每次变化即时重新校核。
- 保留“算法推荐 / 销售选择 / 待工程确认”三种视觉标识。

### 打印预览与工程交接

- 打印预览只读取冻结的 handout manifest，固定显示方案号、修订号、当地时间/IANA 时区、UTC 偏移和初步方案声明。
- 销售选择 `zh-CN`、`en`、`ru` 或 `uk` 和 PDF/DOCX 格式后提交审核；只有状态为 `APPROVED_FOR_DELIVERY` 的文件才显示“打印/交付客户”。
- 提交工程前展示交接清单：答案完整度、销售改动、客户偏好、警告、附件和客户已拿到的文件。
- 工程接收后，销售看板持续显示“已接收 / 优化中 / 待补充 / 正式方案已发布”。

### 项目需求页

- 分组问卷：项目、矿石、设计基础、产品、工艺目标、场地、道路、基础设施。
- 每个字段显示单位、来源、确定/估计/未知、证据附件。
- 右侧持续显示完整度、冲突、阻断项和建议补充项。
- 保存草稿与提交快照明确分开。

### 推荐结果页

三栏：左侧项目/场景导航；中间流程图和设备；右侧证据、规则、假设、排除原因。

顶部固定显示：技术状态、证据覆盖、工程审核状态、输入版本、算法/规则/设备/案例版本。

### 工程方案工作台

- 中央 React Flow 画布。
- 左侧工艺模块/设备类型库。
- 右侧选中节点/边/设备属性和说明。
- 底部校核、警告、变更差异和历史。
- 算法原稿与当前修订可并排/叠加比较。
- 自动保存只保存草稿，不自动提交审核。

### 审核页

- 输入摘要与变更范围。
- 算法候选 vs 工程修订差异。
- BLOCKER/WARN 列表和覆盖理由。
- 每段流程说明、设备能力和依据。
- 批准/退回必须填写意见；批准动作二次确认。

### 初步客户文件审核页

- 只有 BMS 权限映射到 `customer.handout.review` 的指定人员可进入待办和执行决定，不依赖“团队负责人”职级。
- 并排显示冻结的 manifest 摘要、语言、PDF/DOCX 预览、免责声明版本、生成者和 checksum。
- 退回必须写原因；批准前再次校验文件 checksum。默认不能审核自己生成的文件。
- 这是现场文件审核，不显示为工艺审核或正式工程批准。

### 数据更新中心

- 入口要求 `sales_platform.data_maintain`；具体 BMS 权限码待集成契约确认。
- 新导入、AI 提取、待审核变更、冲突、过期数据、影响范围、发布历史。
- 字段级 old/proposed/source/unit/confidence 对比。
- 不允许把“一键导入”设计成绕过审核的正式写入。

### 内容管理中心

- 页面树管理公司、乌兹别克斯坦子公司、生产能力、产品功能和授权案例；区块支持 Hero、图文、Gallery、Metric、Document、Case Card。
- 四语言矩阵显示 `MISSING / DRAFT / STALE / IN_REVIEW / APPROVED`，支持并排预览和逐字段差异；LLM 只生成待审核草稿。
- 媒体库显示原图、响应式 variant、checksum、尺寸、焦点、使用页面、权利来源与到期状态；图片含文字时可按 locale 覆盖。
- 预览覆盖桌面、窄屏和客户模式；发布前显示实际 release manifest，不用草稿数据假装已发布。
- 内容发布权限与工程数据维护权限分开；编辑、翻译、审核、发布和媒体管理使用独立逻辑权限。

上述内容管理和数据治理能力可通过同一 Sales Platform Admin API 在 BMS 管理控制面呈现。若独立平台也保留这些页面，两端必须共享权限、版本和状态机，不允许形成两套数据或两种发布语义。复杂流程图编辑、推荐解释和大文件工作台统一深链回独立平台。

## 3. 前端状态

- 服务端状态：TanStack Query（实现阶段确认版本）。
- 表单：schema 驱动，建议 React Hook Form + Zod。
- 画布编辑：本地 command stack + 服务端修订；保存时带 `rowVersion`。
- 长任务：SSE 更新，断线后轮询恢复。
- 不把正式业务状态只放 Redux/localStorage。

## 4. 流程图编辑器

节点应显示：工艺段编号、名称、设计流量、状态、设备摘要、警告数量。端口必须有工程语义，如 FEED、OVERSIZE、UNDERSIZE、OVERFLOW、UNDERFLOW、CONCENTRATE、TAILINGS、RECYCLE_WATER。

交互要求：

- 拖入节点时先选工艺类型，再加载参数 schema。
- 连边时校验端口类型，非法连接即时阻止或明确标红。
- 删除节点前显示受影响边、设备和说明。
- 循环连接要求选择循环角色并确认。
- 复杂图支持分组/子流程，但持久化仍保存完整图语义。
- 一次输入只触发一次状态转换，避免重复保存/重复提交。

## 5. Electron 安全边界

BrowserWindow 基线：

```text
nodeIntegration: false
contextIsolation: true
sandbox: true
webSecurity: true
```

同时：

- CSP 默认 `script-src 'self'`；
- 只加载打包本地 UI 或受控 HTTPS；
- 限制导航、新窗口、下载和外部链接；
- IPC handler 验证 sender、channel、参数 schema 和权限；
- Preload 每个能力一个函数，不暴露通用 IPC；
- 文件保存使用用户选择的目标和安全文件名；
- 自动更新包必须签名并校验发布渠道；
- Token 优先系统安全存储/短会话，不长期明文放 localStorage。

依据：<https://www.electronjs.org/docs/latest/tutorial/security>

## 6. Web 与 Desktop 复用

前端计划放在独立仓库：Electron Main/Preload 只做安全壳，React 功能放共享 Web package。桌面特有能力通过 `DesktopBridge` 接口注入，浏览器实现提供下载/文件选择降级。Electron 的确可以像桌面程序打开同一套网站功能，但仍必须分别处理 Windows/macOS 的安装包、代码签名、自动更新、打印、保存路径和安全策略。

Windows 与 macOS 在同一首发批次交付，功能版本号与 API 契约一致；平台特有缺陷可分别发布修复，但不能让其中一个长期成为二等客户端。

内容更新不触发 Electron 应用更新。应用启动、恢复联网或收到发布通知时使用 ETag 拉取 current ContentRelease；完整下载并校验 checksum 后原子切换。本地缓存只保存已发布 release，失败/离线时继续使用上一完整版本。

## 7. 可访问性与国际化

- 键盘可完成表单、审核与主要画布操作；图节点有列表替代视图。
- 颜色不作为唯一告警手段。
- 数字、单位、日期本地化，但 API 标准单位不变。
- 首期支持中文 `zh-CN`、英语 `en`、俄语 `ru`、乌克兰语 `uk`；俄语与乌克兰语是独立翻译版本。
- 客户关键文本缺少目标语言翻译时阻止交付，不静默混用另一语言；LLM 只能生成待审核翻译草稿。
- UI 使用用户偏好时区，项目页面同时显示矿山所在地时区；文件显示生成地/项目时区与 UTC 偏移。

## 8. 防止数据误用

- 草稿、算法候选、已审核、已发布使用清晰且一致的状态样式。
- 过期/被替代版本默认禁止下载为“当前方案”。
- 报告预览显示水印和版本号。
- 未发布设备规格或规则在 UI 中明确隔离，不可被推荐任务选择。
- 客户模式和内部模式使用服务端不同 projection，不只是用 CSS 隐藏敏感字段。
- 初步打印件与正式工程发布使用不同颜色、标题、编号类型和水印，不允许视觉上混淆。
